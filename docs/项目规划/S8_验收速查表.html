日志为什么是"限频"的

USER 态每 1.5 s 走一遍决策，而"脸不合格""冷却期内"是常态不是异常 —— 无条件打日志 5 分钟能刷 200 行同样的字，把有用的行冲走。 所以新增 skip_log(slot, fmt, ...)：按原因槽各自限频 30 s，共 7 个槽 （quality / cooldown / no_sd / no_db / no_mem / busy / enroll_quality）。
真正异常的路径（commit 失败、水印画布缺失）仍然 ESP_LOGE 无条件打。

顺手修掉的一处哨兵值滥用

recog_pump() 原来用 pr.elapsed_ms != 0 判"这次打卡任务跑完了"。 但 elapsed_ms 以 tick（10 ms）计，而 punch_task 有几条 同一 tick 内立刻失败的早退路径（参数不对 / SD 未挂载 / 目录拼不出来） ⇒ elapsed_ms == 0 ⇒ "打卡失败"永远弹不出来，用户只看到"按了没反应"。
修法：punch_record_t 增加显式字段 bool has_result， punch_task 收尾无条件置位，UI 改判它。
规矩统一为：状态用显式标志位，不要拿测量值当哨兵（本工程第二次踩到）。
