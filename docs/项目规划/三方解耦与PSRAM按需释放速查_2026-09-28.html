一句话结论

CAM 页拆成三个各管各的功能，每个都有独立完整的开始与结束：

功能所有者开始结束
face/hand 检测（espdet）FACE(det) 按钮 按下 → 加载按下 → 停检测（模型常驻，D6 不变）
识别引擎（MSR/MNP+MFN）打卡 或 录入 会话 会话开始 → 按需加载会话结束 → 彻底释放
录入用的检测录入流程借用 进 ENROLL 自动开录入结束归还 + 彻底卸载
旧病根：det 开着 ⇒ 2.3 MB 识别引擎常驻 现在：谁需要、谁加载、谁释放 det 按钮 = 纯检测开关

改前的耦合病根：recog_pump() ③ 的 want = face_service_enabled() && face_model_active() && state==RUNNING && db_ready ⇒ 只要 det 按钮开着，2.3 MB 识别引擎就一直占着，用户不打卡也占。

2. 解耦的三个关键改动（tab_camera.c）

① 需求判据换成 recog_need()（全页唯一真相源）

static bool recog_need(void) {
    if (s_mode == CAM_MODE_ENROLL) return s_enroll_state != ENROLL_OFF;  /* 录入会话 */
    return s_punch_armed;                                                /* 打卡会话 */
}
bool want = recog_need() && face_db_is_ready() && camera_service_is_running();

不再引用 face_service_enabled() / face_model_active() / face_service_state() —— 那三个是 det 按钮的领地。

② 打卡不再依赖 espdet 的框

删掉 ④ USER 分支的 if (!q.ok) return;。识别引擎自带 MSR+MNP （自己检脸 + 5 点关键点），根本不需要 espdet 的框；旧的"先便宜后昂贵" 前置门把打卡和 det 按钮焊死在一起了。代价 = 一次按下真跑一次 MSR+MNP+MFN （≈400 ms），但打卡是手动触发，可接受。

③ det 的所有权模式（s_det_borrowed）

  • 进 ENROLL 时若检测没开 ⇒ 借用（置 borrowed）+ 自动开；
  • 录入结束（enroll_finish_to_user()，唯一出口）⇒ 只归还借来的： set_enabled(false) + face_service_unload()；
  • 用户手动碰 FACE 按钮 ⇒ 所有权立即转移给用户（清 borrowed）， 录入退出不再代为归还 —— 否则用户自己按开的开关会被流程悄悄关掉。

3. 新增 face_service_unload()（检测侧的"彻底释放"）

函数语义
face_service_stop() 只翻 enabled，模型常驻（D6）—— .h 里 "Stop and release model / PSRAM" 旧注释与实现不符，已改正
face_service_unload()（新） 停检测 + 卸模型 + free scratch（172,800 B）+ state=IDLE

为什么只能在 cam_task 执行（所以只投递意图 s_unload_req）：

  • unload_all() 删的是 esp-dl 模型对象，构造/析构都该在 cam_task；
  • s_scratch 正被 face_service_detect() 每帧写 （同在 cam_task），在 LVGL 线程直接 heap_caps_free() 就是 UAF。

防乱序：set_enabled(true) 时若卸载请求还未消费，拒绝并告警 —— 否则"先卸后建"的顺序会乱，且卸载分支会把这个加载请求一起清掉。

保留 s_last_good_id：下次 set_enabled(true) 仍回到上次成功的档位。

7. 上机判据

  1. 冷启动进 CAM 页：串口不应出现 recog engine ready 或 [modelmem] "FACE" —— 什么都不加载。
  2. 只按 FACE：model "FACE" ready；再按 ⇒ detect OFF | model stays resident（常驻，D6）。
  3. 按 PUNCH：recogmem pre ... → recog engine ready in ~1.2 s → punch submitted (async) → 随后必须出现 recog engine released（≈2.11 MB 还回去）。
  4. 录入：进 ENROLL（det 本来没开）⇒ det borrowed for ENROLL； 采完入库 ⇒ detect OFF + model UNLOADED (PSRAM returned, scratch freed) + recog engine released。两笔都还干净。
  5. 录入中途手动按 FACE ⇒ 退出录入时不再有 UNLOADED（所有权转移生效）。
  6. 时间显示：连网 ⇒ 画布左侧两行 2026.09.28 / 22:58:06 每秒跳； 断网 ⇒ 什么都不显示。
  7. 录像/拍照：MEDIA_BUF_CNT=2 需要 2.64 MB 连续块 —— 打卡/录入结束后 PSRAM 已还干净，这条链路应更容易成功。

不需要 storage-flash，build → flash 即可。

8. 没做 / 边界

  • 没改 face_service_stop() 的 D6 常驻语义 —— 只有录入借用的检测才在结束时卸载。
  • 没做 canvas 缓冲与 punch 帧/JPEG 缓冲的会话化释放（lazy 分配、量小、复用价值高）。
  • 录入期间手动把 FACE 关掉会停在 capturing 0/3 并给出提示 （录入确实需要检测，引导会说明）。
