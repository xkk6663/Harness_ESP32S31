# 08 代码风格

## 格式

- 缩进 4 空格，不混用 Tab；
- 行宽 ≤ 120 字符；
- `{` 不换行（K&R 风格）：
  ```c
  if (x) {
      foo();
  }
  ```
- 函数之间空两行。

## 命名风格

- 函数 / 变量：`snake_case`；
- 宏 / 枚举值：`UPPER_SNAKE`；
- 类型：`lower_snake_t`；
- 不使用匈牙利记号。

## 头文件

- 必须 `#pragma once`；
- `extern "C"` 包裹；
- 按顺序 include：标准库 → ESP-IDF → BSP → LVGL → 本模块。

## 错误处理

- 初始化失败用 `assert()`（开发期），运行期用 `ESP_LOGE` + 降级；
- 不要吞返回值：
  ```c
  // 不推荐
  read(fd, buf, len);
  // 推荐
  ssize_t n = read(fd, buf, len);
  if (n < 0) { ESP_LOGE(...); }
  ```
- 资源配对：`open` 必 `close`，`malloc` 必 `free`，`jpeg_dec_open` 必 `jpeg_dec_close`。

## 日志与调试

> 本工程靠 `docs/_serial_capture.py` 抓 COM9 日志做闭环验收，日志写得好不好直接决定定位速度。

### TAG 与级别
- 每模块一个静态 TAG，与模块同名、大写：`static const char *TAG = "AUDIO_SVC";`；
- 级别：`ESP_LOGE`=错误（带 `esp_err_t`/对象/参数）；`ESP_LOGW`=可恢复异常/降级；
  `ESP_LOGI`=状态迁移与关键节点；`ESP_LOGD/V`=细粒度调试（默认关）；
- 禁止用 `printf`，一律走 ESP_LOGx（带 TAG/时间戳/级别/可过滤）。

### 什么必须打（闭环验收全靠这些）
- 启动按序打点：FS 挂载 `LittleFS mounted at ... total= used=`、`audio_service ready`、
  codec 打开 `ch= bits= rate= size=`、WiFi `got ip`、页面 `PAGE_MGR: load X`、进主界面；
- 命令下发（PLAY_FILE/REC/START/STOP）打一行，不带高频数据。

### 什么绝对不能打（高频路径）
- 音频每帧/I2S 回调/udp 每包循环**禁止 ESP_LOGI**（会爆音丢帧）；
- 丢包/乱序/水位/栈水位改为**每 2s 聚合打一条**；不打印整段 PCM/payload。

### 错误日志必须带上下文
- 统一格式 `动作 + 对象 + 原因/错误码`：
  `ESP_LOGE(TAG, "%s open failed, err=%d", path, err);`；
- 不允许只写 `"open failed"`、`"error"`。

### 可观测与 grep 验收
- 状态迁移每次进新态打一行；统计值统一前缀 `STAT: loss=.. jitter=.. rb=.. stack_hwm=..`；
- 验收 grep：`FS_SVC | AUDIO_SVC | WIFI_MGR | WP_OVERLAY | PAGE_MGR | main | UDP_VOICE | LINK`；
- panic 看 `Guru/abort/E (`，用 addr2line 反查 PC（见 skill 第 6 节）；
- 新模块上线，启动日志必须能 grep 到 `xxx init done`。
