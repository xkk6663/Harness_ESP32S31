# 05 注释规范

## 文件级

- 头文件 `@brief` 一句话，复杂模块再加 `@note` / `@warning`；
- 不要在注释里写被注释掉的旧代码，直接删。

## 函数级

公共函数在头文件用 `/** ... */` 块注释：

```c
/**
 * @brief 下发一条音频命令（线程安全）
 * @param cmd 命令结构体，不能为 NULL
 * @note  非阻塞入队，满了直接丢
 */
void audio_service_post_cmd(const audio_cmd_t *cmd);
```

## 行内注释

- 关键逻辑、硬件坑位用 `/* */` 注释，不要 `//`（本工程 .c 用 C 风格注释）；
- 为什么这么做比做了什么重要：

```c
/* MCLK=GPIO42 未连接，必须 use_mclk=false（硬件坑位，勿改） */
```

## 禁止

- ❌ 注释掉的死代码（git 会记历史）；
- ❌ 头文件里写函数实现；
- ❌ 在注释里写 `// TODO: 后续优化` 而不关联 issue/todo。
