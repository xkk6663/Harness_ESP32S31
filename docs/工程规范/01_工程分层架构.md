# 01 工程分层架构

> 本工程严格按 **APP 层 / middleware 中间层 / ui 层** 三层划分，禁止跨层调用。
> 层内按**领域**再分子目录，避免单目录文件平铺。

## 目录

## 归位规则（新增文件时判断放哪）

| 文件特征 | 放到 |
|---|---|
| `app_main()` 及其编排逻辑 | `app/` |
| 驱动 codec / I2S / 录音 / 会话仲裁 | `middleware/audio/` |
| A2DP / AVRCP / 推流 / 链路状态 | `middleware/bluetooth/` |
| WiFi / SNTP / HTTP 拉取 | `middleware/network/` |
| 按键 / LED / 文件系统 / SD 卡 | `middleware/system/` |
| 页面注册与切换 | `ui/ui_manager/` |
| 全屏页面（`page_` 前缀） | `ui/pages/` |
| 主框架标签页（`tab_` 前缀） | `ui/tabs/` |
| 覆盖在页面之上的浮层（`overlay_` 前缀） | `ui/overlays/` |
| 被多个页面共享的部件或主题常量 | `ui/common/` |
| 字体、图标等生成资源 | `ui/assets/` |

## 依赖方向

```
app        →  middleware + ui
ui         →  middleware（只通过 post_cmd / 事件回调，不直接碰硬件）
middleware →  BSP / ESP-IDF 驱动（bsp_*, esp_codec_dev, i2s, spi_flash）
```

**中间层内部**允许的方向（`middleware/` 子目录之间）：

```
system  ←  (被依赖，不反向依赖)
network ←
audio   →  system（fs_service）/ bluetooth（link_manager）
bluetooth → system（button_service）/ audio（session_manager）
```

> 实测：`middleware/` 对 `ui/` 的 include 引用数为 **0**，分层红线未被破坏。
> 新增中间层模块时**不要**引入对 `ui/` 的引用。

### ⚠ 已知的方向倒挂（待修，见 `12_音频链路架构.md` §4.4）

`middleware/bluetooth/link_manager.c` 里 `#include "middleware/audio/udp_voice.h"`，
并在解析到 `SESSION_START` / `SESSION_STOP` 时直接调 `udp_voice_post_cmd(...)`。

这形成 **`bluetooth → audio`** 的反向依赖，与上表声明的
`audio → bluetooth（link_manager）` **方向相反**。它同时也是把"信令分发"
硬编码到具体业务的例子（加第三条音频链路时必须再改 `link_manager`）。

**修法**：`link_manager` 扩一个信令事件（复用现有 observer 队列），
由 `udp_voice` 自己订阅，`link_manager` 不再 include `udp_voice.h`。

> 另注：`link_manager` 管的是 **UDP 50003 信令与 peer 状态**，本质属网络层，
> 放在 `bluetooth/` 已属勉强。彻底的归位应移入 `network/`，但会牵动本文件与
> `改动记录.md §20`，建议与上面的解耦一起做，不要单独搬家。

## 禁止事项

- ❌ middleware 层 `#include "lvgl.h"`（中间层不认识 LVGL）；
- ❌ ui 层直接 `xTaskCreate` 硬件任务、直接 `esp_codec_dev_write`；
- ❌ ui 层直接 `i2c_master_*` / `i2s_*` 寄存器操作；
- ❌ app 层写业务逻辑，只做初始化顺序；
- ❌ 跨层 `extern` 别人的 static 变量；
- ❌ `#include "../xxx.h"` 相对路径；
- ❌ 裸文件名 `#include "ui_theme.h"`（跨目录时必须写全路径 `ui/common/ui_theme.h`）。

## 层间通信

| 方向 | 机制 | 例子 |
|---|---|---|
| ui → middleware | 命令队列 `audio_service_post_cmd(&cmd)` | 点播放按钮 → `AUDIO_CMD_PLAY_FILE` |
| middleware → ui | 事件回调 `audio_service_set_evt_cb()` | 播放完成 → UI 解锁按钮 |
| middleware → middleware | FreeRTOS 队列 / 任务通知 | audio_task 与 net_task 通过 ringbuf 传 PCM |
