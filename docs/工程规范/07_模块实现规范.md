# 07 模块实现规范

## 常驻任务 + 命令队列 模式（本工程核心）

硬件业务模块统一用这个模式，**不要**在 UI 事件回调里临时 `xTaskCreate`。

### 标准结构

```c
// 1. 命令枚举 + 结构体
typedef enum {
    MOD_CMD_START,
    MOD_CMD_STOP,
} mod_cmd_id_t;

typedef struct {
    mod_cmd_id_t id;
    char path[256];
    int  value;
} mod_cmd_t;

// 2. 事件枚举（模块完成后通知 UI）
typedef enum {
    MOD_EVT_STARTED,
    MOD_EVT_STOPPED,
} mod_evt_id_t;

// 3. 私有状态：队列、任务、回调、句柄
static QueueHandle_t s_cmd_queue;
static mod_evt_cb_t  s_evt_cb;
static SemaphoreHandle_t s_mux;

// 4. init：创建队列、互斥锁、常驻任务
void mod_init(void) {
    s_cmd_queue = xQueueCreate(4, sizeof(mod_cmd_t));
    s_mux = xSemaphoreCreateMutex();
    xTaskCreate(mod_task, "mod_task", 8192, NULL, 6, NULL);
}

// 5. post_cmd：UI 唯一入口，非阻塞
void mod_post_cmd(const mod_cmd_t *cmd) {
    xQueueSend(s_cmd_queue, cmd, 0);
}

// 6. 事件回调注册
void mod_set_evt_cb(mod_evt_cb_t cb) { s_evt_cb = cb; }

// 7. 任务主循环：等命令，执行，发事件
static void mod_task(void *arg) {
    static mod_cmd_t cmd;
    for (;;) {
        if (xQueueReceive(s_cmd_queue, &cmd, portMAX_DELAY) != pdPASS) continue;
        switch (cmd.id) {
        case MOD_CMD_START: handle_start(&cmd); break;
        case MOD_CMD_STOP:  handle_stop();      break;
        }
    }
}
```

## 栈大小

- 业务任务栈默认 **8192 字节**（不是 4096，命令结构带 path[256] 会撑爆）；
- 栈帧里的大结构体（>200B）改 `static`；
- 出现 `0xa5a5a5a5` 栈填充 → 先加栈。

## 互斥锁

- 保护硬件并发访问用 `xSemaphoreCreateMutex`；
- 在 `init()` 里创建一次，**不要**在窗口打开时创建、关闭时销毁；
- 持锁时间要短，锁内不要 `vTaskDelay`。

## 事件回调

- 事件回调在**业务任务上下文**被调用（audio_task / iot_button task / wifi event task 等），
  **不是 LVGL task**。
- 回调里**严禁直接调用任何 `lv_*` API**（按钮 enable/disable、改文字、设值等都不行）。
  原因：LVGL 非线程安全，跨任务并发访问控件 → 偶发 Cache error / 黑白闪屏 / hard fault
  （见 `11_遇到的问题.md`：REC 按钮事件在 audio_task 里 `bsp_display_lock(0)` 抢不到锁仍操作控件导致崩溃）。

## 跨任务访问 LVGL：队列解耦（硬规范，红线）

**唯一允许的模式**：业务任务只 `xQueueSend` 事件 ID，LVGL task 经 `lv_timer` 出队后再碰控件。

```c
// UI 层（page_xxx.c）：建队列 + lv_timer（在 LVGL task 上下文 init）
static QueueHandle_t s_evt_q;

static void drain(lv_timer_t *t) {              // 跑在 LVGL task，可直接 lv_*
    evt_t evt;
    while (xQueueReceive(s_evt_q, &evt, 0) == pdPASS) {
        apply(evt);                              // 在这里更新按钮/标签/滑块
    }
}

void xxx_register(void) {
    s_evt_q = xQueueCreate(8, sizeof(evt_t));
    lv_timer_create(drain, 30, NULL);           // 30ms 节拍
    mod_set_evt_cb(on_evt);                     // 业务任务回调只入队
}

// 业务任务上下文：绝不 lv_*，只投递
static void on_evt(evt_t evt) {
    xQueueSend(s_evt_q, &evt, 0);              // 满了丢，UI 状态以最后一次为准
}
```

### 红线清单
1. **业务/中间层 task 内不得出现 `#include "lvgl.h"` 和 `lv_*` 调用**（中间层本就禁止碰 UI）；
2. **从非 LVGL task 发起 UI 更新**：一律 `xQueueSend` 到 UI 队列，由 LVGL task 的 `lv_timer` 出队执行；
3. **禁止用 `bsp_display_lock(0)`（非阻塞）后不判断返回值就操作 LVGL**——拿不到锁等于裸奔；
   也不要在业务任务里 `bsp_display_lock(portMAX_DELAY)`（可能与 LVGL task 互相等锁死锁）；
4. **高频/高实时事件**（按键、音量、音频帧、网络包）用任务通知 `xTaskNotifyGive` / 队列，
   禁止轮询（`while` + delay）和在中断/回调里做重活；
5. **共享硬件状态**（RMT/I2S/SPI/LCD/LED）：多任务不直接调同一组驱动 API，
   用"命令队列 + 单 worker 任务"串行化（参照 led_service）；
6. 队列深度取 4~8，元素只放事件 ID/小结构体；跨任务传指针要保证生命周期（静态池或 malloc 后由消费方释放）。

### 反例（禁止）
```c
// 业务任务上下文 —— 错！
static void on_audio_done(audio_evt_id_t e) {
    bsp_display_lock(0);                 // 非阻塞，拿不到也往下走
    lv_obj_clear_state(btn, LV_STATE_DISABLED);  // 跨任务碰 LVGL → 崩溃
    bsp_display_unlock();
}
```
