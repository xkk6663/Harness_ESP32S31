## 2. 整体架构

```
LVGL UI (tab_camera.c)
   │ 按键事件
   ▼
camera_service.c (新建)
   ├─ OV3660 DVP 采集（esp_video / esp_cam_sensor）
   ├─ 双 FrameBuffer + Bounce Buffer（PSRAM）
   ├─ color_hsv.c（HSV 阈值检测 + 框选标记）
   └─ ai_service.c（esp-dl，按需隔帧推理）
          │
          ▼
LittleFS /littlefs/models/*.espdl
```

**启动时序**：
```
nvs_init → wifi → fs_service_mount(/littlefs) → lvgl_port_init
   → camera_service_init(只初始化不采集)
   → camera_tab_create(注册三按键)
```

模型不在启动时加载，而是按"按键3 按下"才加载（懒加载，省 PSRAM）。

## 3. Camera Tab 三按键定义

| 按键 | 功能 | 实现 |
|---|---|---|
| BTN_PREVIEW | 预览开/关 | `camera_service_start_preview()` / `stop()` |
| BTN_HSV | HSV 颜色识别开/关 | 叠加色块标记（在 preview 帧上画矩形） |
| BTN_AI | AI 推理开/关 | 懒加载 .espdl 模型，隔帧推理画人脸框 |

**画面模式**：
- 小窗口预览（默认）：Camera Tab 内 320×240 窗口
- 全屏预览：双击画面切全屏 800×480，再切回小窗口

## 4. 图像缓冲方案（防撕裂）

ESP32-S31 有 2D-DMA + PPA，但摄像头预览走 LVGL 显示缓存的标准做法：

1. **OV3660 输出**：YUV422 / RGB565，DVP DMA 写入 PSRAM bounce buffer
2. **双 FrameBuffer**：LVGL v9 的 `lv_display_set_buffers()` 配两个 PSRAM buffer，前后帧交替
3. **帧拷贝**：camera task 拿到一帧 → 等 LVGL 锁 → `lv_canvas_set_buffer()` 或 `lv_draw_img` 刷新 → 释放锁
4. **隔帧推理**：AI 推理每 3 帧跑一次，不绑定每帧回调

**内存预算（PSRAM 16MB）**：
- 摄像头双 bounce buffer：800×480×2 = 1.5MB
- LVGL draw buffer 2×：800×480×2(RGB565) = 1.5MB
- AI 模型 + tensor：~3MB
- 剩余：~10MB 给其他

## 10. 风险

| 风险 | 对策 |
|---|---|
| DVP 与 RGB LCD 争抢 PSRAM 带宽 | 摄像头输出 RGB565 直接喂 LCD，避免 RGB888 转换 |
| AI 推理占满一个核 | AI task 绑 core1，LVGL/音频绑 core0，隔帧推理 |
| 模型 >8MB LittleFS 装不下 | 优先用量化模型（<2MB），或后续加 SD 卡 |
| DVP 引脚与现有外设冲突 | 板级头已确认无冲突（LCD 用 GPIO 8-18/33-36，CAM 用 46-57） |
