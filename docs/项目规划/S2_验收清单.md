## 3. S2a —— 拍照（VIDEO tab 的【CAPTURE】）

操作：插卡 → 进 VIDEO tab → 点【CAPTURE】。

| # | 判据 | 通过标准 |
|---|---|---|
| 3.1 | `[ ]` 日志出现完整事务 | `I (xxx) CAPTURE: capture -> /sdcard/photos/IMG_20260925_XXXXXX.jpg` → `photo OK: NNNNN bytes, 4 frames seen` → `capture done: err=ESP_OK, NNN ms` |
| 3.2 | `[ ]` SD 卡上真有 `.jpg` | 拔卡到 PC：文件存在、**双击能正常打开**（这是"传感器真的输出 JPEG"的硬证据） |
| 3.3 | `[ ]` **拍完自动回预览** | 切回 CAM tab：预览自己在跑（状态显示 `Preview running` / 按钮为 `STOP`），人脸检测继续可用。日志里应有 `I (xxx) CAPTURE: preview restored` |
| 3.4 | `[ ]` 连拍 10 张无失败 | 连点 10 次（每次等 1~2 s），10 张都出现、`capture done: err=ESP_OK`，且 `[mem]` 的 `largest internal` 不下降 |
| 3.5 | `[ ]` ⚠ **实测：整个事务耗时** | 读 `capture done: ... NNN ms`。预期**数百 ms**。**> 3000 ms 就要优化**（方案 §9 的验收条件） |
| 3.6 | `[ ]` VIDEO tab 空闲时显示结果 | 卡片上出现 `last photo: NN KB in NNN ms (4 frames)` |

**异常对照**：
- `no usable frame in 6000 ms (seen 0)` → 起流后完全没帧：多为 JPEG 档切不过去（看上一行的 `sensor switch` 是否有 `E`）。
- `fwrite short: a/b bytes, errno=28` → `errno 28 = ENOSPC`，**卡满了**（不是代码问题）。
- `take over (stop preview) failed` → CAM 页预览没停干净，`cam_task` 卡住了。

## 4. S2b —— 录像（VIDEO tab 的【REC】）

操作：进 VIDEO tab → 点【REC】（按钮变红 `STOP REC`）→ 录 30 s → 点【STOP REC】。

| # | 判据 | 通过标准 |
|---|---|---|
| 4.1 | `[ ]` 录制中仪表盘动 | 卡片显示 `REC  00:12   NN KB` / `frames NNN  fps N.NN  max frame NN KB`（★ **2026-09-25 实测修正**：fps **实测 14.54，高于标称 12** —— OV3660 的 `12fps` 只是 DVP 描述符标称值，不是硬上限。判据改为"**与 12 同量级；明显低于 5 才算异常**"） |
| 4.2 | `[ ]` 停止后进入"保存中" | 状态行变成 `SAVING - do NOT remove the card`，**UI 不卡死**（能继续点别的 tab） |
| 4.3 | `[ ]` 收尾日志完整 | `I (xxx) RECVID: rec done: err=ESP_OK reason=user frames=NNN bytes=NNNNNN max_frame=NNNN fps=N.NN sec=NN` |
| 4.4 | `[ ]` **VLC / 电影播放器能播，且时长与录制时间一致** | 播 30 s 录的片子，播放器显示时长 ≈ 30 s（这是 `avi_muxer_set_real_fps` 的作用；若时长明显短于 30 s 说明实测 fps 没写进去） |
| 4.5 | `[ ]` 录完自动回预览 | 同 3.3 |
| 4.6 | `[ ]` 录像期间 CAM 页置灰 | 录制中点 CAM tab：按钮变灰 + 状态 `Cam busy: VIDEO recording`，**不是**"按下去没反应" |
| 4.7 | `[ ]` **录到一半拔卡** → 系统不崩 | 状态行转 `SAVING`，日志见 `abort muxer (reason=write error)` + `rec done: err=... [aborted, no idx1]`；重启后 SD 卡仍能正常挂载 |
| 4.8 | `[ ]` ⚠ **实测三笔账**（这是 §2.5.7 风险 1 的答案） | ① `max_frame` 多少 KB？② 实测 fps 多少？③ 收尾（`STOP REC` → 状态行回到 `Idle`）耗时几秒？**把这三个数记下来即可** |

**异常对照**：
- `muxer write failed (code -1)` → `AVI_ERR_IO`，卡满/卡拔/只读。
- `cam_task still alive -> muxer/FILE intentionally leaked` → 相机任务停不下来，本轮录像作废（**需要重启**）；把日志贴回来。
- `avi_muxer_close failed` → 回填/索引失败，文件仍可能能播但缺索引（UI 会显示 `(NO INDEX)`）。

## 7. 明确"不在范围内"（不要按 bug 报）

| 现象 | 说明 |
|---|---|
| 拍照/录像时屏幕上看不到画面 | **设计如此**（方案 §5.2：VIDEO tab 不做实时预览）。★ **2026-09-25 用户实测后提出异议** ⇒ 已列为待决变更，见 `S2_验收日志分析_2026-09-25.md` §4 |
| **整个 VIDEO tab 都没有画面**（不只是拍照/录像时） | **设计如此** —— 该页是"遥控器 + 仪表盘"（标题/状态行/信息卡片/3 个按钮），**没有图像控件**。★ 同上，待决 |
| 录像 fps 只有 3~8，达不到标称 12 | **设计如此**（用"降 fps"换"零丢帧 + 零额外 PSRAM"，方案 §5.1-④）。★ 实测本次为 **14.54**，见 §4.1 |
| 录像文件没有声音 | **设计如此**（一期不做音频，用户 2026-09-25 20:37 已确认） |
| 拍完照片后 CAM 页预览"自己又开始跑了" | **设计如此**（方案 §2.5.4 的"归还"） |
| 录音页（REC tab）录音到 ~165 s 就停 | **存量已知问题**（littlefs 分区只有 ~5.2 MB 可用，与本次改动无关） |

## 8. 出问题时先抓这三样

1. **完整串口日志**（从 `SDCARD: mounting SD card to /sdcard ...` 开始，到出错为止）。
2. **`[mem]` 每一行**（`after xxx` 分步账单）——内部 RAM 是本工程最容易踩的坑。
3. **`[stack]` 那张表**（开机时打印的全任务水位）。

> 定位口诀：**只信真值，不信推断**。日志里没有的数，就当作"不知道"，不要用"应该是……"结论。
