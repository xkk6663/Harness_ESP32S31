### D6 为什么定"常驻"（这是与上一轮方案的最大差别）

`[resident]` 实测数据（`face_service.cpp` D3 埋点，上机日志）：

```
load #1  INT free 154375->154111 (-264) | largest 67584->67584 (0)
load #1  DMA free 122403->122139 (-264) | PSRAM free 11127220->10039216 (-1088004)
unload #1 PSRAM +1090640
```

⇒ **一个模型常驻的代价 = 1.038 MB PSRAM + 264 B 内部 RAM，且 `largest` 零变化。**
PSRAM 当时 free 11.1 MB，扣掉还剩 ~10 MB。

**换来三件事**：
1. 免掉每次进相机页的 0.5~1 s 模型加载等待；
2. 免掉反复 `new/delete` 的碎片风险（不再有"加载→卸载"账目配不平的机会）；
3. ★ **把"模型加载期花屏"限制在开机后第一次** —— 日志实测加载期 `memcpy16k max=602 us`
   （预算 444 us 的 **136%**，是全部场景里最差的一档），这是实打实的花屏窗口。
   常驻之后这个窗口只出现一次。

**明确不接受的代价**：模型在 PSRAM 里不会释放，相机页退出后仍占 1.038 MB。已确认可接受。

### 2.2 ★ 两处"没人告诉你但会踩"的配置

**(a) `HUMAN_FACE_DETECT_MODEL_SDCARD_DIR` 的默认值只管 S3/P4，不管 S31**

```kconfig
# 组件 Kconfig 原文
default "models/s3" if IDF_TARGET_ESP32S3
default "models/p4" if IDF_TARGET_ESP32P4     ← 没有 ESP32S31 分支
```

⇒ 本工程必须在 `sdkconfig.defaults:97` 手写 `CONFIG_HUMAN_FACE_DETECT_MODEL_SDCARD_DIR="models"`。
**已存在，不要删**。它决定了实际路径是 `/littlefs/models/<name>`。

**(b) ★★ `HUMAN_FACE_DETECT_MODEL_SDCARD_DIR` 是编译期常量**

⇒ **S1 的 registry 不能靠"换目录"来切变体**（那要重编译）。目录固定 `/littlefs/models/`，
切档只切**枚举值**。这也意味着 §6 的 p4/s3 A/B **必须换文件内容**，不能换路径。

### 2.3 ★★ esp-dl 对 S31 用的是 **P4 的 ISA 后端**

```cmake
# managed_components/espressif__esp-dl/CMakeLists.txt:55
elseif(CONFIG_IDF_TARGET_ESP32P4 OR CONFIG_IDF_TARGET_ESP32S31)
    list(APPEND src_dirs     dl/tool/isa/esp32p4)
    list(APPEND src_dirs     dl/base/isa/esp32p4)
    list(APPEND src_dirs     ./vision/image/isa/esp32p4)
```

对照 S3 走的是 `dl/*/isa/xtensa` + `dl/*/isa/tie728`（Xtensa TIE 指令）。
**S31 与 P4 同组、与 S3 不同组** —— 这是 §6 结论的直接依据。

### 2.4 图像输入是自适应的，与模型档位无关

```cpp
// dl_detect_base.hpp
class Detect { virtual std::list<result_t> &run(const dl::image::img_t &img) = 0; };
// DetectImpl 内部用 dl::image::ImagePreprocessor（ESPDet 构造时 enable_letterbox({114,114,114})）
```

⇒ `run()` 接受**任意尺寸**的 `img_t`，由 `ImagePreprocessor` 负责 resize/letterbox 到模型输入。
⇒ **`tab_camera` 传 240×240 对三档都成立，不需要为 416 档改任何调用。**

⚠ **但要说清一个易误解点**：416 档吃 240 输入 = **插值放大**，不增加信息。
它**不会比 224 档更准**，只会更慢。它真正的用途是将来相机改出更高分辨率
（`CONFIG_CAMERA_OV3660_DVP_YUV422_YUYV_640X480_10FPS` 这个格式**已存在于组件里**、当前 = n）。
**S1 把它当"档位"上（成本只是 1 个文件 + 1 次加载），但不要指望精度提升。**

## 3. S1 设计

### 3.1 数据结构（`face_service.cpp` 内部，不出头文件）

```cpp
/* 三档同族：全走 HumanFaceDetect，只是枚举不同 ⇒ 条目只需要"枚举 + 文件名"映射。
 * ★ 不引入 create/destroy/infer 函数指针 —— 那是给"异族模型"（S2）准备的；
 *   现在引入只会多一层间接、多一堆没人读的代码。S2 需要时再把 entry 升级。 */
typedef struct {
    face_model_id_t id;
    const char     *label;       /* UI 短文案（ASCII：bin 字体不含生僻字风险） */
    int             hfdet_enum;  /* HumanFaceDetect::model_type_t */
    const char     *files[2];    /* NULL 结尾；MSRMNP 有 2 个 */
} face_model_entry_t;

static const face_model_entry_t s_models[] = {
    { FACE_MODEL_ESPDET_224, "224",
      HumanFaceDetect::ESPDET_PICO_224_224_FACE,
      { "espdet_pico_224_224_face.espdl", NULL } },
    { FACE_MODEL_ESPDET_416, "416",
      HumanFaceDetect::ESPDET_PICO_416_416_FACE,
      { "espdet_pico_416_416_face.espdl", NULL } },
    { FACE_MODEL_MSRMNP_S8,  "MSR",
      HumanFaceDetect::MSRMNP_S8_V1,
      { "human_face_detect_msr_s8_v1.espdl",
        "human_face_detect_mnp_s8_v1.espdl" } },
};
```

**★ 不硬编码输入尺寸**：构建成功后从 `get_raw_model()->get_inputs()` 打一行真实 shape。
硬编码会写错（MSRMNP 的输入尺寸本期没查到），而且模型真值本来就能读。

### 3.2 状态机（复用现有 4 值，**UI 不用改**）

| 现有状态 | 新语义 | 备注 |
|---|---|---|
| `FACE_IDLE` | 无模型（UNLOADED） | 开机初始 |
| `FACE_LOADING` | **首次构建** 或 **切换中**（SWITCHING） | 两者共用；3 s 看门狗照常生效 |
| `FACE_RUNNING` | 有可用模型（READY） | 常驻后**不再回到 IDLE** |
| `FACE_FAIL` | 构建失败且无 last_good | UI 已能显示 |

⇒ **`face_state_t` 一个字节都不用动**，`tab_camera.c` 的 `refresh()` 现有分支继续有效。

### 3.3 "模型就绪" 与 "检测开关" 解耦（D6 的必然结果）

常驻之后，`face_service_stop()` 不能再删模型，于是必须区分两个概念：

```c
/* 新增（C ABI，UI 是 C 层）*/
esp_err_t   face_service_set_enabled(bool on);  /* 检测开关；不碰模型 */
bool        face_service_enabled(void);
/* 档位接口 */
int         face_service_model_count(void);
const char *face_service_model_label(int id);
int         face_service_current_model(void);
esp_err_t   face_service_request_model(int id); /* 异步：置请求，cam_task 的 poll 执行 */
```

`face_service_detect()` 的守卫从 `s_state != FACE_RUNNING` 扩成
`s_state != FACE_RUNNING || !s_enabled`。

**UI 文案映射（`tab_camera.c`）**：

| 模型状态 | enabled | 按钮文案 | 颜色 |
|---|---|---|---|
| `FACE_RUNNING` | true | `FACE ON` | 绿 |
| `FACE_RUNNING` | false | `FACE` | 灰 |
| `FACE_LOADING` | — | `LOAD...` | 黄 |
| `FACE_FAIL` | — | `FAIL` | 红 |
| `FACE_IDLE` | — | `FACE` | 灰 |

### 3.4 切换时序（D8 + D9 + D11）

```
face_service_request_model(id)          ← LVGL 线程，只置 s_pending_model + s_model_req
        ↓
cam_task → face_service_poll()          ← 唯一的执行点（零新任务）
        ↓
① 文件预检：s_models[id].files[] 逐个 stat("/littlefs/models/<f>")
        缺任一 ⇒ ESP_LOGE + 拒绝 + 清 s_model_req（**不动现有模型**）   ← D11
        ↓ 通过
② s_state = FACE_LOADING
③ delete s_detector（先卸）             ← D8：峰值 = 一个模型
④ new HumanFaceDetect(enum, false)      ← 构造函数内即 load_model()
        失败 ⇒ 尝试用 s_last_good_id 重建；再失败 ⇒ s_state = FACE_FAIL
⑤ 成功 ⇒ s_cur_id = id；s_last_good_id = id；s_state = FACE_RUNNING
```

**为什么 D11 是 D8 的必要配套**：先卸后建的话，若新模型文件不存在，旧的已经卸了、
新的建不起来 ⇒ 用户**当场失去可用模型**。预检把这种情况挡在"卸"之前。

### 3.5 生命周期（D6）

| 事件 | 行为 |
|---|---|
| 开机 | 不加载（`FACE_IDLE`） |
| 第一次按 FACE | 构建默认档 ⇒ `FACE_RUNNING` |
| 再按 FACE | 只 `set_enabled(false)`，**模型留着** |
| 切档 | §3.4 流程 |
| 离开相机页 / `cam_task` 退出 | **模型留着**（`s_detector` 不删；`run()` 自然不被调用） |
| 只有"显式释放"才卸 | S1 先不给入口；S2/内存告急时再加 |

## 6. p4 vs s3 变体：**已定稿用 p4**（2026-09-25 用户拍板，跳过 A/B）

> **决策（最终）**：**采用 p4 变体、不做 A/B**（用户 2026-09-25 决定）。
>
> ⇒ **无需更换任何文件**：`littlefs_content/models/` 下 4 份权重经 `cmp` **逐字节**核对，
> **全部 `== models/p4/`、且全部 `!= models/s3/`**。
> ★ 特别记一笔：`human_face_detect_mnp_s8_v1.espdl` 在 p4/s3 下**尺寸完全相同（129,968 B）**
> ⇒ **只看 `ls` 分辨不出**，必须用 `cmp`。以后核对这份别偷懒。
>
> ⚠ **诚实边界**：A/B **没有做过** ⇒ "s3 变体在 S31 上会失败/退化"这句**仍然是推断**
> （依据 §6.1 的逐字节差异 + §6.2 的 esp-dl 编译分支），**不是实测**。
> 这条已登记到 §8.3 末尾的验收清单，**别当成已验证事实**。
>
> ⇒ 下面的 §6.1~6.3 保留为**决策依据**，以及"万一将来要复议"时的操作手册。

### 6.1 二进制对比（本次实测，逐字节）

| 文件 | p4 | s3 | 差异字节 | 差异段数 | ≥64 B 的长段 | 最长段 |
|---|---|---|---|---|---|---|
| `espdet_pico_224_224_face.espdl` | 495,840 | 495,872 | **461,218（93%）** | **17,314** | **2,254** | 635 B |
| `espdet_pico_416_416_face.espdl` | 499,376 | 499,232 | 461,596（92%） | 16,980 | 2,109 | 734 B |
| `human_face_detect_msr_s8_v1.espdl` | 61,248 | 61,168 | 48,060（78%） | 5,468 | 123 | 387 B |
| `human_face_detect_mnp_s8_v1.espdl` | 129,968 | 129,968 | 115,072（88%） | 4,988 | 376 | 486 B |

头部 8 字节相同（`45444c32` = `EDL2` 魔数），**第 8 字节起就分叉**。

**判读**：差异**遍布整份文件**、且含 **2,254 段 ≥64 B 的长连续段**
⇒ 这不是"元数据多了个 chip id"，而是**同一套网络的**两套算子实现（机器码/ISA 不同）。
个别元数据差异只会是零散几十字节。

### 6.2 与 esp-dl 的编译分支完全吻合

- S3 → `isa/xtensa` + `isa/tie728`（Xtensa TIE）
- **S31 与 P4 → `isa/esp32p4`**（`CMakeLists.txt:55`）

⇒ **s3 变体是给 Xtensa 准备的，S31 是 RISC-V、和 P4 同一套后端。**
**p4 变体才是本芯片的原生选择**；s3 变体大概率加载失败或退化为无加速路径。

### 8.2 实现过程中发现并处理掉的 5 个新问题（方案里没预见到）

| # | 问题 | 处理 |
|---|---|---|
| 1 | **相机没跑时，切档/首次构建的请求无人消费** —— `face_service_poll()` 只由 `cam_task` 调用，相机停了就没人处理 ⇒ 状态卡在 `FACE_LOADING`、3 s 后看门狗判 FAIL | UI 两个回调里前置检查：`FACE` 按钮只在"模型未就绪"时要求相机在跑（已常驻时只翻 bool，无相机也能开）；`MODEL` 按钮一律要求先开相机，提示 `Start camera first` |
| 2 | **`refresh()` 只看 `state` 会让 FACE 按钮永远显示 "FACE ON"** —— 常驻后 `state` 长期是 `FACE_RUNNING`，"检测开着没有"只能看 `enabled()` | 文案/颜色改为按 `(state, enabled)` **两个值**决定 |
| 3 | **原来 `face_btn_cb` 和 `refresh()` 各写一套文案/颜色** ⇒ 两个状态机早晚不一致 | 收敛为**单一真相源**：`refresh()` 是唯一写文案/颜色的地方，回调只发动作 |
| 4 | **按了切档按钮文案不动** —— `target_model_id()` 返回的是旧档位 | 让它优先返回 `s_pending_id`（有未完成请求时 UI 显示**目标**档位） |
| 5 | **`tab_camera_destroy()` 漏清 `s_btn_face` / `s_btn_face_label` / `s_face_bbox`** ⇒ 页面销毁后仍指向已释放对象，`refresh()` 一旦用到就是 UAF | 顺手补齐（含新增的 MODEL 两个指针） |

另：`do_build()` 里给"卸"单独记了一笔 `[resident] unload #N` 账 —— §5-16 的
"反复切档 N 次后 `largest` 不单调下滑"这条验收判据就是靠 load/unload 两笔账配对看出来的。
